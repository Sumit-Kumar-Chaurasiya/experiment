# Experiment Repository

Welcome to my experiment repository.

This is a place where I learn, experiment, break things, fix them, and try out ideas without worrying too much about making everything perfect.

Unlike my production projects, the code in this repository may be incomplete, messy, experimental, or completely useless outside of learning. That's intentional.

The main purpose of this repository is **learning by doing**.

---

## About This Repository

I created this repository as my personal playground for software development.

Whenever I want to:

* Learn a new technology
* Test a framework or library
* Try a new programming concept
* Understand how something works internally
* Build a small proof of concept
* Test an API
* Experiment with UI/UX
* Try a different approach to solving a problem
* Reproduce and fix an error
* Test something before using it in a real project

I can do it here.

Some experiments may only take a few minutes, while others may turn into larger projects.

There is no strict rule that everything here needs to be finished.

---

## Repository Philosophy

> Learn → Experiment → Break → Debug → Understand → Improve

I don't want this repository to contain only successful experiments.

Errors and failed experiments are also part of the learning process.

Sometimes the most useful thing I can learn from an experiment is understanding **why something didn't work**.

## Experiments

The repository is organized around experiments rather than traditional application features.

A typical experiment might look something like this:

```text
experiments/
├── experiment-01/
├── experiment-02/
├── experiment-03/
├── experiment-04/
└── ...
```

Each experiment can have its own purpose, implementation, and notes.

Some experiments may be completely independent from each other.

## Experiment Structure

```text

├── src/
├── assets/
├── tests/
└── notes/
```

The structure is not strict.

The goal is simply to make it easier to understand what I was trying to do.

## Why I Keep Experiments in a Separate Repository

I don't want to experiment directly inside my serious projects.

Production projects usually need:

* Clean architecture
* Consistent coding standards
* Stable dependencies
* Proper testing
* Security considerations
* Maintainable code

An experimental repository gives me freedom to try things without worrying about breaking an important project.

If an experiment works well, I can later rebuild the idea properly in a real project.

## Important

Nothing in this repository should automatically be considered production-ready.

Before using any code from here in a real application, I should review:

* Security
* Error handling
* Performance
* Validation
* Architecture
* Dependencies
* Maintainability
* Testing

An experiment proves that something **can work**.

It does not necessarily prove that it is **ready to be used**.

## Goal

The long-term goal of this repository is simple:

**Learn more by building more.**

Instead of only reading documentation or watching tutorials, I want to experiment with ideas myself.

Some experiments will succeed.

Some will fail.

Some will be completely abandoned.

And some may eventually become the foundation of something much bigger.

## Final Note

This repository is essentially my digital laboratory.

It is where I can ask:

> "What happens if I try this?"

Then actually try it.

If it breaks, I debug it.

If it works, I understand it.

If it turns out to be useful, I take what I learned and build it properly somewhere else.

**This repository is not about showing perfect code.**

**It is about showing the process of learning.**
